# Public page and screenshot provenance

The public Senda page follows a warm editorial direction modelled on [Granola](https://www.granola.ai) (inspected 28 October 2026): large regular-weight serif headings, a white page with cream (#F7F7F2) panels behind product views, pill buttons, no boxed cards or rules between sections, and one dark band. Anchor links scroll smoothly unless the visitor prefers reduced motion. It keeps the Ink + Teal identity. Headings use Newsreader, self-hosted through `@fontsource-variable/newsreader`; body text stays in the interface's system sans-serif. The warm marketing tokens are scoped to the `.marketing` wrapper in `src/web/styles.css`, so the app's colors are unchanged. The artwork (`src/web/components/path-art.tsx`) is generated SVG in ink: winding contour lines after the logo's path, with a light grain. Use it only behind the hero illustration, so the page has two coloured areas: that panel and the dark "Why not just ask your AI for a diagram?" band. Sections run: a centered headline, one sentence and CTAs; the transcript-to-model illustration; audience; a three-step walkthrough with a sticky step list; the comparison with asking an AI on its own, as two short paragraphs; method, privacy and open-source notes; agent setup with an example conversation; FAQs; and a closing CTA. No eyebrow labels, badges or captions that only restate what a visual shows. Write copy to the voice and style rules in the writing folder of Hanif's Obsidian vault. Copy and layout were reviewed with Opus 5.5 through the local Claude Code CLI, then checked against the implemented workflow. See [brand assets and color roles](branding.md).

Live references were inspected and visually captured on 27 October 2026:

- [Eraser AI diagrams](https://www.eraser.io/product/ai-diagrams): clear action/outcome hierarchy, two visible entry actions and an early product illustration. We use a concrete workflow rather than its speed claims, branding or images.
- [IcePanel](https://icepanel.io/): leads with the continuing value of a shared model and uses a large product view. We borrow the idea of exploring detail from a compact overview, without copying the brand, mascot, customer marks or broader architecture/governance proposition.

Images in `public/marketing` are captures of the running application's public onboarding example. Desktop previews use SVG; the mobile evidence preview uses PNG so its text and drawer controls remain correctly positioned in mobile image renderers. The evidence view shows Finance's deposit-invoice step alongside transcript quotations. The clarification view shows the first draft's question about parallel Finance/Delivery work and the join before setup. The overview capture of the revised process is still generated but is not on the page: at page width its detail is too small to read.

The original transcript and clarification fixtures remain documented in `examples/complex-onboarding`. Public copy uses short process and source labels, with captions explaining what a visitor can explore. Keep it direct and affirmative. Do not add repeated fixture disclaimers, speculative limitations or implementation details to product copy. Explain relevant decisions through concrete actions. Customer results and named client integrations need supporting evidence.

The hero illustration in `src/web/components/interview-to-model.tsx` is a drawing, not a screenshot. It places Luis's Finance passage from the onboarding transcript above a simplified version of revision 5's Finance subprocess. Keep its step names and quote in line with `public/examples/onboarding-final.json`; its window bar links to the full model in the example. The example conversation in the agent section paraphrases the README prompt and the first draft's revision summary and first question. Transcripts don't always name speakers, so don't promise that Senda shows who said something; it shows the passage a step came from.

Name a commercial agent client on the page only after its connection flow has been tested (see [hosted compatibility](hosted.md)). Until then, describe the requirement in plain terms: a remote MCP server with OAuth sign-in. Keep the homepage pricing, provider disclosures, usage terms and FAQ consistent with the current Free and Pro plans. The homepage `#pricing` section is the pricing destination; `/pricing` redirects to it.

The worked example is publicly reachable at `/example`; the first draft is `/example?draft=true`. Private review links require account access.

## Sharp product previews

Desktop previews preserve the app's HTML text, SVG diagrams and styles inside SVG `foreignObject` elements. They contain no scripts or remote images. Media queries and viewport units are resolved at capture time so a preview scales without changing its layout. The mobile evidence preview is a screenshot of the real dialog, preserving its wrapping and close control without relying on `foreignObject` layout. The marketing page links each preview to the corresponding live example view.

Earlier WebP assets included desktop captures enlarged from 1× images. Enlarging an image does not recover text detail. Keep desktop diagram lines and lettering as vectors, and capture the mobile dialog at its actual display width.

1. Build and open the local app's public `/example` route in the browser.
2. Use the read-only `capturePreview` function in [capture-preview-dom.js](../scripts/capture-preview-dom.js) with the browser's evaluate API for the three desktop vector captures. Capture evidence and overview at 1200 × 800; clarification at 600 × 1000, cropped to `.reading-column [data-slot="accordion-item"]`. Save the results as `evidence-vector.json`, `overview-vector.json` and `clarification-vector.json` in one capture directory. Open the evidence panel and fit each diagram before capturing it.
3. At 390 × 844, open `/example?view=FinanceWork&element=Invoice`, choose **View evidence**, and capture the **Step evidence** dialog, including its title and close button, as `evidence-mobile.png` in the same directory. Wait for the opening animation to finish or disable animations during the screenshot. The resulting dialog image is approximately 390 × 718.
4. Run `npm run build:marketing -- <capture-directory>`. The builder validates and writes the three desktop SVGs and copies the mobile PNG. To refresh only the mobile image, use `node scripts/build-marketing-previews.js <capture-directory> --mobile-only`; this needs only `evidence-mobile.png` and leaves the desktop captures unchanged.
5. Update the preview URL version in `src/web/components/marketing.tsx`, then visually check the images as embedded images on desktop and mobile. Check that the mobile evidence crop is complete and that each image opens its intended example view.
