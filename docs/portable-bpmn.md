# Portable BPMN layouts and programmatic repair

## Export contract

The whole-model **Download BPMN** and fresh bundle `model.bpmn` contain the original complete process with improved BPMN Diagram Interchange (DI). Shape bounds, connection waypoints, label positions, lane order as displayed, collapse state and child planes come from the same layouts used in the review. Process definitions, semantic element IDs, ownership, lane memberships, conditions and original message endpoints are retained. No project revision or human feedback is created by exporting. The immutable source bytes remain in `model-original.bpmn`.

The download icon inside the diagram offers **BPMN view** and **SVG image**. A standalone view is a partial model matching the selected overview/subprocess and its visible external participants. Subprocess work is promoted to a non-executable process for this artifact; outside endpoints may be represented by their participants. BPMN documentation identifies the scope and original endpoints. Use the complete model for further process editing, rather than silently replacing it with a view.

The complete file has a normal overview plane and separate planes for collapsed subprocesses. Standard child planes retain internal geometry, but omit external context pools/messages because that representation is not interoperable with bpmn-js subprocess navigation. The view files provide those exchanges without inventing new semantics in the complete model. Exact pixel appearance is not guaranteed across editors: fonts, wrapping, navigation controls and DI support differ. A 32px label gutter below the lower-right subprocess corner accommodates bpmn-js's common drill-down control; this is a compatibility heuristic. The coordinates and waypoints are portable; run an import check in the target editor before sharing.

Version 2 bundles identify the format in `discovery.json`. Review grouping and evidence continue to use original XML. Legacy exports still load and get fresh portable downloads in the web app; their historical files are not overwritten. Produce a new bundle to update offline downloads.

## Verification

The subsequent [ELK experiment](elk-evaluation.md) compares an alternative layout engine on the complex onboarding case. It also led to a generic correction allowing routes through intervening lane bodies while preserving title and node clearance.

Automated tests strip DI and compare the complete export with the saved model, compare each exported plane's geometry with its review, inspect original message endpoints, check standalone documentation and coverage, and ensure the saved project/evidence/history are unchanged. Bundle readers check both the main and original files against directory traversal and symlink escapes. Old and new export formats remain grouped as the same process revision when their source content is identical.

Cross-editor validation uses bpmn-js Modeler 18.31.1 independently of Miragon: import the complete model, navigate all child planes, import each standalone view, save and reparse, and compare semantic definitions, endpoint references and DI geometry. This does not establish identical rendering in every BPMN editor. Review the intended editor's result, especially labels and external context.
